# Decisions — 設計判断と未決定事項

> 状態: 初稿（v0.1） / 整理日: 2026-10-15  
> この文書は会話での**合意**と、まだ検証していない**仮案**を混同しないための記録。日付は初稿整理日であり、各判断がその日に初めて行われたという意味ではない。

## 1. 合意済みの方向性

| ID | 決定 | 理由・設計意図 |
| --- | --- | --- |
| D-001 | **Godot 4系で始める。** | ゲーム制作特有の概念や2D向け編集機能を学びつつ、制作へ集中するため。Phaser/Ebitengineも比較したが今回はGodotを優先。 |
| D-002 | **戦闘重視、探索は初作品として控えめ。** | まず戦闘の面白さを成立させ、大規模マップの制作負荷を抑えるため。 |
| D-003 | **片手で完結するシンプルな操作。** | 複雑な入力より、敵の観察・位置取り・ギミック理解に難しさを置くため。 |
| D-004 | **A/D移動、Spaceジャンプ、Shiftダッシュ、W通常攻撃、S+Spaceすり抜け足場。** | 操作キーを少数に保つ。すり抜けは最初から使える。 |
| D-005 | **ジャンプ中も横方向に移動でき、地上・空中で攻撃できる。** | 立体的な戦闘にも対応し、操作の軽快さを維持するため。 |
| D-006 | **ダッシュは移動と回避を兼ね、短い無敵時間を持つ。** | 技術的な回避の別解を残す。ただし万能にはしない。 |
| D-007 | **スタミナを採用しない。** | ギミック理解と攻撃・回避の判断を中心にし、管理要素を増やさないため。 |
| D-008 | **通常攻撃は単発攻撃の繰り返しで、コンボを中心にしない。** | 間合い・タイミング・位置取りによって深さを生み、制作量も抑えるため。 |
| D-009 | **通常攻撃には短いダッシュキャンセル不可時間があり、後半はキャンセル可とする方向。** | 攻撃のリスクと操作の軽快さを両立するため。 |
| D-010 | **ダッシュ入力の先行受付を設ける。** | 硬直解除直前の入力を取りこぼさないため。保持時間は未決。 |
| D-011 | **小型雑魚は1対1なら制圧できてもよい。1対多の配置で判断を生む。** | 雑魚単体を複雑にしすぎず、敵の組み合わせで奥行きを作るため。 |
| D-012 | **一部の雑魚敵にはモーション依存のスーパーアーマーを与える。** | 攻撃連打で永久拘束できる状態を避け、敵の動きを観察させるため。 |
| D-013 | **ボスは通常攻撃では基本怯まず、ギミック時のみ限定的にブレイク可能。** | ギミックを強力すぎる拘束手段にしないため。 |
| D-014 | **ボスの知識を蓄積・再利用する。** | 序盤の法則を後半に別演出や複合パターンで出し、習熟を実感させるため。 |
| D-015 | **初見突破必須ではなく、複数回の挑戦を通じて学ぶ難易度。** | ギミックを推測・学習して倒す体験を中心にするため。 |
| D-016 | **序盤は平坦なボス部屋、後半は高低差のある部屋も採用。** | プレイヤーの操作習熟に合わせてアクション要求を高めるため。部屋はボスのコンセプトに合わせる。 |
| D-017 | **ボス撃破によって既存アクションが拡張される成長方式。** | 新ボタンを増やさず、戦闘と探索の双方を発展させるため。 |
| D-018 | **空中ダッシュを後から解放する。** | 能力獲得によって移動・戦闘の選択肢を広げるため。どのボスで解放するかは未決。 |
| D-019 | **通常攻撃で弾を反射する能力を成長候補とする。** | 専用パリィボタンなしで、戦闘と装置起動等のギミックに応用するため。 |
| D-020 | **Codexで小さく実装し、毎段階コードと操作感を理解する。** | ゲームの完成だけでなく、Godotとゲーム制作を学ぶため。 |
| D-021 | **設計資料をMarkdownで残し、最終像と現在の実装範囲を分ける。** | 実装を小さく区切っても設計意図を失わないため。 |

## 3. 未決定事項・プレイテストで決める数値

- **移動:** 速度、加速・減速、空中方向転換の強さ、ジャンプ高度、重力、落下速度。
- **ダッシュ:** 距離・速度・持続時間、無敵フレーム、再使用条件、敵の当たり判定をすり抜けるか。
- **攻撃:** 発生・持続・硬直、ダッシュキャンセル可能な時点、先行入力の保持時間、攻撃範囲。
- **敵:** 怯み時間、復帰条件、スーパーアーマーの開始・終了、複数体の攻撃頻度。
- **ボス:** 具体的な攻撃順・ギミックの数・ブレイク時間・リトライ導線。
- **成長:** 空中ダッシュと弾反射の獲得順、反射できる弾の条件。
- **作品:** 正式タイトル、世界観、画面サイズ、公開先、最終ボス数・部屋数、ピクセルアート制作方法。
- **操作:** `E`キーの能力が必要か、キー再割り当て・ゲームパッド対応。

## 5. 記録の運用

- 新しい決定をしたら、**何を・なぜ・どの範囲で**決めたかを記録する。
- 仮案を実験しただけで、合意済みの決定へ自動昇格させない。
- 設計を変更したら、旧判断を消すだけでなく、変更理由が追える形にする（変更履歴の追記等）。
- 細かな仮パラメータはコード・Inspectorで調整し、ここでは重要な方針だけを残す。
