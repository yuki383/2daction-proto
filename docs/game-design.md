# Game Design — 操作・戦闘・成長・探索

> 状態: 初稿（v0.1） / 更新日: 2026-10-15  
> **凡例:** **[合意]** 方向性として合意済み / **[仮案]** 推奨・検証候補 / **[未決]** まだ決めていない。  
> 実装範囲は [`prototype-spec.md`](prototype-spec.md) を優先し、将来仕様を先行実装しない。

## 1. 操作

基本は**キーボード左手だけ**で完結することを目指す。

| 入力 | アクション | 状態 |
| --- | --- | --- |
| `A` / `D` | 左右移動 | [合意] |
| `Space` | ジャンプ | [合意] |
| `Shift` | 左右方向のダッシュ／回避 | [合意] |
| `W` | 単発の通常攻撃 | [合意] |
| `S + Space` | すり抜け可能な足場から降りる | [合意]・最初から使える基本操作 |
| `E` | 特殊能力（候補） | [未決]・キー追加自体も未確定 |

- **[合意]** 通常攻撃は同じ単発攻撃を繰り返す。コンボは初作品の戦闘の中心にしない。
- **[合意]** 地上・空中の両方で通常攻撃できる。
- **[合意]** ジャンプ中にも左右へ移動・方向転換できる。
- **[合意]** 空中ダッシュはボス撃破によって後から解放する方向。地上ダッシュは最初から使用可能。
- **[仮案]** `Space`の押下時間でジャンプ高度が変わる。コヨーテタイム、ジャンプバッファを導入する。
- **[未決]** キーボード以外の操作方式、キーコンフィグ、攻撃の上下方向、`E`の最終的な用途。

## 2. 移動・回避

### 2.1 ジャンプ

- **[合意]** 空中制御を重視し、ジャンプ後にも着地点を調整できる。
- **[仮案]** 短押しの小ジャンプ／長押しの高ジャンプを可能にする。
- **[仮案]** 入力の取りこぼしを軽減するため、コヨーテタイムとジャンプバッファを採用する。
- **[未決]** 移動速度、加減速、ジャンプ高度、落下速度、空中制御率などの数値。

### 2.2 ダッシュ

- **[合意]** 移動能力と回避能力を兼ねる。ダッシュの一部に短い無敵時間を設ける。
- **[合意]** 無敵だけで全ギミックを処理できないようにする。ただし、本来は位置取りで解くギミックを、難しいタイミングの無敵回避で突破できる余地は残す。
- **[合意]** 瞬間的な攻撃と持続する攻撃を区別する。持続攻撃は無敵終了後の位置が危険なら被弾し得る。
- **[合意]** 基本は左右方向へダッシュする。
- **[仮案]** 空中ダッシュは着地まで1回、着地で回数回復。使用中の落下を短時間抑える。
- **[未決]** ダッシュ速度・距離・全時間・無敵開始／終了・再使用制限・敵の身体のすり抜け可否。

無敵を貫通する例外攻撃を安易に増やすより、攻撃判定の継続時間や攻撃範囲で対処方法の違いを作る。

### 2.3 すり抜け足場

- **[合意]** すり抜け可能な足場から`S + Space`で下へ降りる。これは獲得能力ではなく最初から使える操作。
- **[仮案]** 後半のボスでは上下の足場移動をギミックに組み込む。
- **[未決]** 入力の優先順位、すり抜け開始時の落下挙動、足場を再び踏める条件。

## 3. 通常攻撃と操作のリスク

### 3.1 通常攻撃

- **[合意]** `W`で単発近接攻撃。連打しても基本は同じ攻撃を繰り返す。
- **[合意]** 空中での攻撃が可能。軽快なレスポンスを優先する。
- **[合意]** 攻撃の一部時間はダッシュでキャンセルできない。硬直後半はキャンセルできる方向。
- **[合意]** ダッシュ入力の先行受付（入力バッファ）を取り入れ、操作の取りこぼしを減らす。
- **[未決]** 攻撃範囲・発生速度・持続・全硬直・キャンセル開始・バッファの保持時間。

攻撃を以下のような時間区間に分けて検討する。

```text
攻撃開始
  ├─ 予備動作（startup）
  ├─ 攻撃判定の発生（active）
  ├─ 硬直前半（recovery / キャンセル不可）
  └─ 硬直後半（recovery / ダッシュキャンセル可）
攻撃終了
```

以前議論したフレーム数（例: 全20F）は**確定値ではない**。敵の予兆や回避性能と一緒にプレイテストで調整する。

### 3.2 攻撃ヒット時の反応

ダメージ、ヒット演出、行動中断を別の要素として考える。

| 概念 | 内容 |
| --- | --- |
| ダメージ | HPなどへの実際の影響 |
| ヒットリアクション | 命中音・点滅・斬撃エフェクト・短いヒットストップ等の手応え |
| 怯み（stagger） | 敵の現在の行動を中断して、短く行動不能にする状態 |
| スーパーアーマー | ダメージは受けるが、怯みを防ぐ性質 |
| ブレイク | 特定のギミック成功などによる、ボスの限定的な行動中断 |

※演出の具体的な作り方、ヒットストップ量は[未決]。

## 4. 雑魚敵

### 4.1 小型・基本型

- **[合意]** 1対1なら通常攻撃で制圧できる程度の敵がいてよい。
- **[合意]** 1対多では敵の位置や攻撃順、プレイヤーの立ち位置が問題になるようにしたい。
- **[仮案]** 最初は単純な接近型から試作し、その後に複数体配置して検証する。

「簡単な敵を複数置いただけで、理不尽な同時攻撃になる」ことは避けたい。敵の予兆の見やすさと、挟み撃ち時の逃げ道はテストする。

### 4.2 スーパーアーマーを持つ敵

- **[合意]** スーパーアーマーは敵の種類だけでなく、**特定の行動モーション**に紐づける。
- **[合意]** スーパーアーマー中でも基本的にダメージは通る。
- **[重要]** スタミナも攻撃コンボ制約もないため、「予備動作の前半を攻撃で毎回中断できる」仕様を安易に採用しない。攻撃連打による永久拘束を避ける。
- **[仮案]** 剣士型の敵は、怯みから復帰した直後にスーパーアーマー付きの反撃モーションを開始できる。あるいは攻撃開始から一部モーションを中断不能にする。
- **[未決]** 怯み時間、怯み中の追撃、復帰時の行動、アーマーの開始・終了タイミング。

プレイヤーには「今は攻撃を止められない」とモーションから読み取れる手掛かりを用意する。

## 5. ボス戦

### 5.1 基本設計

- **[合意]** 通常攻撃ではボスは基本的に怯まず、自分の攻撃パターンを継続する。
- **[合意]** 特定のギミック成功に限って行動を中断させるケースがあってよい。
- **[合意]** ブレイクは限定的なものにし、長時間の一方的な攻撃や連続ブレイクで戦闘を壊さない。
- **[仮案]** ブレイクの報酬は大ダメージだけでなく、大技の中断・短時間の安全な反撃・危険地形の解除なども候補。
- **[合意]** 序盤のボスは平坦なフィールドを主体にし、後半は高低差・すり抜け足場を積極的に使う。フィールド構造は各ボスのコンセプトに合わせる。

### 5.2 ギミックの設計原則

1. **予兆と結果の対応を学べること。** 被弾後に原因を理解できる演出を用意する。
2. **初見で必ず攻略できる必要はないこと。** 何度か挑戦し、法則を理解して上達する難易度を目指す。
3. **知識を横展開できること。** 先に光った場所から攻撃する、という法則を別のボスでも別演出で再利用する。
4. **既存ルールを複合化すること。** 単に新ルールを追加するだけでなく、時間差攻撃と薙ぎ払いなどを組み合わせる。
5. **無敵回避による別解を残すこと。** 単発攻撃は技術次第で無敵突破できる余地を設け、持続攻撃では位置取りが重要になるようにする。
6. **ブレイクは選択肢であって義務にしないこと。** 特殊な中断を狙わなくても倒せるボスを基本にする。

### 5.3 仮の試作ボス「鐘楼の騎士」

**以下は会話で合意した方向性に沿うデザイン例であり、最終採用・数値・演出は未確定。**

| 攻撃 | 予兆 | 回避・対処の考え方 |
| --- | --- | --- |
| 薙ぎ払い | 剣を低く構える | ジャンプ／距離調整 |
| 叩きつけ | 剣を高く振りかぶる | 横移動／ダッシュ |
| 紋章爆発 | 地面の紋章が発光する | 安全地帯へ移動、タイミング次第で無敵回避 |

後半の発展例: 紋章が光った順番で爆発し、さらに薙ぎ払いと組み合わせる。特定の大技の後に弱点を攻撃して短時間のブレイクを誘発できる案もある。

最初のボス試作では攻撃を少数に限定し、**予兆の読みやすさ、無敵回避の余地、反撃機会**を優先的に検証する。

## 6. 成長・探索

- **[合意]** 新しいボタンを増やすより、既存アクションの使い道を増やす。
- **[合意]** 能力解放はボス撃破を主要な契機とする方向。
- **[合意]** 探索は初作品では抑えめにし、戦闘の密度・完成度を優先する。

| 能力候補 | 既存入力 | 戦闘での変化 | 探索での変化 | 状態 |
| --- | --- | --- | --- | --- |
| 空中ダッシュ | `Shift` | 空中での回避・位置調整 | 遠くの足場へ届く | [合意] 解放する方向／詳細は仮 |
| 弾の反射 | `W`の通常攻撃 | 飛び道具を跳ね返して反撃、ギミック中断の契機 | 反射弾で装置や障害物に作用 | [合意] コンセプト／獲得順と仕様は未決 |
| 追加のアクション強化 | 既存入力 | 選択肢を広げる | 通路・障害物に作用 | [未決] |

探索のためだけの複雑な能力ツリーや装備ビルドは、初作品では優先しない。

## 7. 難易度とリトライ体験

- **[合意]** 初見突破よりも、挑戦を繰り返して敵の行動を理解し、習熟で勝てる体験を重視する。
- **[合意]** 難しいギミックでも、被弾の理由は理解できるようにする。
- **[合意]** 後半は操作にもある程度の難易度を要求してよい。ただし序盤で学んだ操作・ルールを積み重ねる。
- **[仮案]** ボスにすぐ再挑戦できる配置・チェックポイントを用意する。

## 8. ドット絵とアニメーション（後続工程）

- プレイヤーのアクション仕様を先に調整し、初期は仮の四角形で検証する。
- キャラクターの見た目、ヒットエフェクト、攻撃判定の責務をなるべく分離する。
- NovelAIの用途はコンセプトアートなどから検討。アニメーションフレーム間で形状・色・位置が揃う制作フローが必要。
- 解像度、スプライト寸法、フレーム数、制作ツールは[未決]。

## 9. 今後優先して検証すること

- 通常攻撃の硬直とダッシュキャンセル開始のバランス
- ダッシュの移動距離・無敵時間・再使用条件
- 空中制御と、後に解放する空中ダッシュの探索・戦闘への影響
- 雑魚敵が攻撃連打だけで永久拘束されないか
- ボスのギミックが分かりやすく、理解による回避と技術的な別解が成立するか
